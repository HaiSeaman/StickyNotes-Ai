# StickyNotes-Ai V1.7 功能重构方案：待办事项解耦独立与归档模块建设

## 1. 概述与重构目标

本方案针对 **StickyNotes-Ai** 的待办事项（Todo）模块进行系统性架构重构。目前版本的待办事项作为字段 `todos: []` 嵌套在具体的便签对象中，导致新建/切换便签时待办列表随之变更或“清空”。

本次重构在**绝对保持现有 UI 布局、交互样式和毛玻璃视觉效果不变**的前提下，达成以下四大核心目标：

1. **待办事项彻底解耦独立**：待办事项升级为全局一等公民实体，拥有独立的持久化存储文件（`todos.json`），不再依附于任何便签，新建或切换便签时待办事项内容保持常驻。
2. **构建待办事项归档文件夹**：新增待办归档能力（存储于 `todos_archived.json`），其弹窗 UI 样式、逻辑和功能（搜索、还原、彻底删除）与现有“便签归档文件夹”完全一致。
3. **增加日期时间维度**：为待办事项新增创建时间（`createdAt`）、更新时间（`updatedAt`）与完成时间（`completedAt`）时间戳，并在待办列表及归档列表中精致渲染格式化的日期时间信息。
4. **清理移除“延期到明天”功能**：彻底移除待办事项的“延期”逻辑、数据字段（`deferred`、`deferredAt`）以及 UI 界面上的“延期到明天”操作按钮。

## 2. 需求拆解与架构设计

### 需求 1：待办事项独立化（解耦便签依附）

* **现有痛点**：数据模型中 `Note` 包含 `todos: [{ id, text, done, deferred, ... }]`。当用户点击“+ 新建便签”或在左侧侧边栏切换便签时，右侧待办面板显示的是 `getCurrentNote().todos`，使得用户误以为待办被清空。
* **设计方案**：
  * 主进程新增 `getTodosPath()`，绑定 `userData/todos.json`；
  * 全局声明独立的 `todos` 状态数组；
  * 移除 `renderNoteList()`、`switchNote()`、`createNote()`、`deleteNote()` 中对 `renderTodoList()` 的数据关联更新；
  * 待办事项不再受便签切换影响，所有待办增删改查均作用于全局 `todos` 数组。

### 需求 2：待办事项归档文件夹（与便签归档逻辑一致）

* **设计方案**：
  * 主进程新增 `getArchivedTodosPath()`，绑定 `userData/todos_archived.json`；
  * 前端 `index.html` 复制 `archiveModal` 的结构与样式，新增 `todoArchiveModal` 模态框，包含标题（带计数器）、搜索框、滚动列表和关闭按钮；
  * 左下角工具栏按钮 `archiveFolderBtn` 功能调整为打开**待办归档文件夹**（或根据布局语义明确分工）；
  * 待办条目新增“归档”按钮（或勾选后自动/手动归档操作），归档后从 `todos` 转移至 `archivedTodos`；
  * 归档模态框支持关键词实时搜索、取消归档（还原至全局待办）以及永久删除。

### 需求 3：待办事项添加日期与时间信息

* **数据结构扩展**：
  ```json
  {
    "id": 1742000000000,
    "text": "完成 V1.7 功能重构方案编写",
    "done": false,
    "createdAt": 1742000000000,
    "updatedAt": 1742000000000,
    "completedAt": null
  }
  ```
* **UI 显示设计**：
  * 保持原有待办列表布局，在待办文本下方或右侧追加一行轻量辅助文字（例如：`03-15 14:30` 或 `完成于 03-15 15:10`）；
  * 使用类似现有便签归档的日期格式化函数 `formatNoteCreatedTime`，保持整体视觉精细度。

### 需求 4：删除“延期到明天”功能与按键

* **清理范围**：
  1. **数据与逻辑**：从 `renderer.js`、`main.js`（Popout 小窗口 HTML 生成器）中彻底删除 `deferTodo()` 函数及 `deferred` 排序加权逻辑；
  2. **UI 元素**：删除 `.todo-defer` 按钮元素、`.todo-defer-badge` 徽章元素及其对应的 CSS 样式；
  3. **小窗口同步**：更新 `buildTodoPopoutHtml` 模板，去除延期按钮与延期统计计数。

### 需求 5：UI 布局零变动保障

* 维持 `index.html` 中的整体 DOM 结构；
* 保持毛玻璃（Glassmorphism）面板、待办列表滚动条、底部工具栏（归档按钮、垃圾桶按钮、待办输入框、添加按钮）的纵向与横向相对位置；
* 所有变动均为内部数据源替换与局部图标功能对齐，不调整 CSS 尺寸、外边距、内边距及 Flex 布局规则。

## 3. 详细数据流与 IPC 通信设计

### 3.1 文件路径定义 (`paths.js`)

```javascript
// 全局待办主数据
function getTodosPath() {
    return path.join(app.getPath('userData'), 'todos.json');
}
// 全局待办归档数据
function getArchivedTodosPath() {
    return path.join(app.getPath('userData'), 'todos_archived.json');
}
```

### 3.2 IPC 通信通道矩阵 (`main.js` & `preload.js`)

| 通道名称 | 类型 | 说明 |
| :--- | :--- | :--- |
| `todos:load` | `handle` | 从 `todos.json` 读取全局待办列表 |
| `todos:save` | `handle` | 异步保存全局待办列表到 `todos.json` |
| `todos:load-archived` | `handle` | 读取归档待办 `todos_archived.json` |
| `todos:save-archived` | `handle` | 保存归档待办到 `todos_archived.json` |
| `todo:popout` | `handle` | 打开独立待办置顶小窗口（改为加载全局待办数据） |
| `popout-todo:input` | `on` | 小窗口修改待办后同步回主窗口 |
| `popout-todo:push-from-main` | `on` | 主窗口修改待办后推送给小窗口 |

## 4. 逐步实施计划 (Implementation Plan)

### 阶段一：持久化层与 IPC 通信升级

1. **修改 `paths.js`**：增加 `getTodosPath` 和 `getArchivedTodosPath` 导出。
2. **修改 `main.js`**：
   - 注册 `todos:load` / `todos:save` / `todos:load-archived` / `todos:save-archived` 处理句柄；
   - 更新 `buildTodoPopoutHtml()` 模板：移除延期按钮，加入时间显示，绑定全局待办数据；
   - 更新退出与崩溃保护钩子中的 `saveTodos` 同步落盘逻辑。
3. **修改 `preload.js`**：向 `window.api` 暴露上述全新的 IPC 调用函数。

### 阶段二：DOM 结构与归档弹窗建设 (`index.html`)

1. **新增待办归档模态框**：在 `index.html` 末尾复制 `archiveModal` 结构，命名为 `todoArchiveModal`：
   - `id="todoArchiveModal"`
   - 标题 `id="todoArchiveModalTitle"`（包含 `todoArchiveCount` 计数器）
   - 搜索框 `id="todoArchiveSearchInput"`
   - 列表容器 `id="todoArchiveList"`
2. **关联右下角工具栏按钮**：确认待办区域左下角 `archiveFolderBtn` 绑定打开 `todoArchiveModal`。

### 阶段三：渲染进程核心逻辑重构 (`renderer.js`)

1. **状态声明与初始化**：
   - 声明 `let todos = []` 以及 `let archivedTodos = []`；
   - 在 `init()` 中通过 `window.api.loadTodos()` 与 `window.api.loadArchivedTodos()` 初始化数据。
2. **重构 `renderTodoList()`**：
   - 彻底解除对 `getCurrentNote()` 的依赖；
   - 渲染每个待办条目时，移除 `.todo-defer` 按钮；
   - 添加时间戳渲染（使用 `t.createdAt` 格式化为轻量时间标签）；
   - 为条目添加“归档”按钮或将删除/归档功能区分开。
3. **实现待办归档与还原控制**：
   - 实现 `archiveTodo(id)`、`restoreArchivedTodo(id)`、`deleteArchivedTodo(id)`；
   - 实现 `renderTodoArchiveList()`，复用 `renderFolderModal` 通用弹窗渲染工具函数。
4. **整理 `addTodo()` 与 `toggleTodo()`**：
   - `addTodo()`：为新对象赋予 `createdAt: Date.now()`, `updatedAt: Date.now()`, `done: false`；
   - `toggleTodo()`：勾选完成时记录 `completedAt: Date.now()`；
   - 移除 `deferTodo()` 相关触发函数与事件监听。
5. **解除便签与待办的耦合**：
   - 在 `renderNoteList()`、`switchNote()`、`createNote()`、`deleteNote()`、`archiveNote()` 中移除对 `renderTodoList()` 的无谓调用。

### 阶段四：日历模块适配 (`renderer/tabs/calendar.js`)

1. 更新日历页面的当日待办展示逻辑：使用全局 `todos`（或带有 `targetDate` 的全局待办）进行渲染，确保日历页待办与主面板待办数据一致。
