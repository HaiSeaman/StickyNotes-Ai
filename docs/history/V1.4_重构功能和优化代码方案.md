# StickyNotes AI - V1.4 功能重构与代码优化专业方案

> **版本标识**: V1.4_Refactor_Plan  
> **文档主题**: 边缘Tab功能剥离、领域驱动模块化解耦与全性能提升  
> **面向对象**: 开发团队、架构师与QA测试工程师  

---

## 1. 重构概述与总体目标 (Overview & Objectives)

### 1.1 背景与现状诊断
StickyNotes AI 经过快速迭代，已具备便签管理、AI 聊天、AI 创作、语音合成 (TTS)、实时翻译、背景音乐/电台、日历闹钟等多丰富功能。但随着代码膨胀，代码库呈现出明显的 **“上帝文件 (God File)”** 趋势：
- 根目录 `main.js`（5,177 行）与 `renderer.js`（5,983 行）合计占全项目 18,074 行代码的 **61.7%**。
- 主界面顶部包含 8 个 Tab，其中“语音 (TTS)”和“翻译 (Translate)”占用大量界面空间与后台 IPC 协议资源，但与软件的核心定位（轻量桌面便签 + AI 工具助手）相关度低。
- 磁盘 I/O 高频落盘、流式 AI 回复高频重排等存在微观 Jank 瓶颈。

### 1.2 总体重构目标
1. **删除边缘功能（Slim down）**：彻底剔除“语音 (TTS)”与“翻译 (Translate)”2 个 Tab 页面的全部 DOM 结构、渲染逻辑、主进程 IPC 通道与协议服务。
2. **按功能域解耦（Domain-Driven Decoupling）**：将平铺在上帝文件中的逻辑剥离为独立的领域模块（IPC 模块、UI Tab 模块、Services 依赖服务），将单文件代码量降至 2,000 行以内。
3. **性能与代码质量提升（Quality & Performance）**：优化磁盘并发 Save 策略，实现流式渲染帧防抖，抽离硬编码数据，建立零泄漏资源生命周期管理。

## 2. 第一阶段：删除“翻译”与“语音”TAB 功能方案

经过深度依赖审计，TTS 与 Translate 在逻辑上是 **100% 自包含 (Self-contained)** 的。与便签、闹钟、AI 聊天、日历等核心功能没有任何强依赖关系。

### 2.1 精细化清洗清单

#### 1) HTML DOM 层 (`index.html`)
- **导航栏精简**: 移除 `<button data-tab="tts">` 与 `<button data-tab="translate">`，Tab 按钮由 8 个缩减为 6 个。
- **视图节点清理**: 删除 `<div id="tab-tts" class="tab-page">` 与 `<div id="tab-translate" class="tab-page">` 内部约 **180 行** DOM 结构（包含音色下拉框、合成按钮、音频播放器、语言切换组件等）。

#### 2) 渲染进程 (`renderer.js`)
- **常数与配置清理**: 删除 `TTS_PRESET_VOICES_BY_MODEL` 数组映射表及相关的 `ttsConfigCache` 缓存变量。
- **DOM 引用提取**: 移除 `ttsBaseUrl`, `ttsModel`, `translateSource`, `translateResult` 等 25+ 个 DOM 引用。
- **事件监听与业务逻辑函数**:
  - 清理 TTS 声音选择、保存设置、语音合成、音频下载及缓存清理等 12 个事件监听器。
  - 清理翻译上传附件、语言选择、执行翻译等 8 个事件监听器。
- **Tab 路由字典更新**: 移除 `tabPages.translate` 与 `tabPages.tts`。

#### 3) 主进程 (`main.js` & `preload.js`)
- **IPC 管道解绑**:
  - 清理 `save-tts-config`, `get-tts-config`, `tts-synthesize`, `tts-save-audio`, `tts-cleanup-cache` 通道。
  - 清理 `translate` IPC 处理器。
- **自定义协议卸载**: 删除主进程对 `ttsfile://` 协议的注册与音频缓存临时目录监听。
- **Preload API 清理**: 移除 `window.api.ttsSynthesize`, `window.api.translate` 等暴露的 ContextBridge 方法。

#### 4) 样式层 (`styles.css`)
- 提取并删除专有 class 选择器：`.tts-voice-info`, `.tts-player-wrap`, `.translate-attach-item`, `.translate-result` 等约 **350 行** 无用 CSS。

## 3. 第二阶段：按功能域解耦方案 (Domain Modularization)

### 3.2 响应式事件总线与状态 Store 设计
取消 `renderer.js` 中的平铺全局变量，引入极轻量级的响应式 Store (Store-Event Bus)：
```javascript
// renderer/store.js
class AppStore {
    constructor() {
        this.state = {
            currentTab: 'notes',
            notes: [],
            chatHistory: [],
            userSettings: {}
        };
        this.listeners = new Map();
    }
    subscribe(key, fn) {
        if (!this.listeners.has(key)) this.listeners.set(key, []);
        this.listeners.get(key).push(fn);
    }
    setState(key, newValue) {
        this.state[key] = newValue;
        if (this.listeners.has(key)) {
            this.listeners.get(key).forEach(fn => fn(newValue));
        }
    }
}
export const store = new AppStore();
```

## 4. 第三阶段：代码量优化与质量提升 (Code Hygiene & Quality)

### 4.1 静态 Prompts 与模型列表剥离
在根目录下新建 `constants/prompts.js` 和 `constants/models.js`，将写死在 `renderer.js` 和 `main.js` 中的文本外置：
- 创作 Tab 的 20+ 种系统角色预设模版外置。
- DeepSeek/Qwen/OpenAI 等模型的默认配置结构外置。

### 4.2 性能提升方案
1. **流式 AI 回复 rAF 防抖 (AnimationFrame Debouncing)**：
   - 废除每收到一个 chunk 就立即更新 DOM 并执行 `join('')` 的方案。
   - 使用 `pendingText += chunk.text` 增量追加，并由 `requestAnimationFrame` 以 60fps 节流刷新视口。
   - 增加 `isScrolledNearBottom` 判断，当用户向上翻看历史记录时，禁止强行霸道置底。
2. **JSON 物理落盘写合并 (Pend-Latest I/O)**：
   - 重构 `json-io.js`，针对同一文件的连续高频写入，只保留队尾最新的待落盘数据指针（`pendingData`），写完后一次性落盘，提升 SSD 写入效率 5x~20x。
3. **内存泄露回收门禁**：
   - 在音效播放、Howler 音轨切换处强制引入 `.off()` + `.unload()`，销毁解码节点。

## 6. 测试要求与质量门禁 (Testing Requirements)

### 6.1 单元测试与断言 (`test_runner.js`)
使用测试套件校验以下指标：
1. **安全校验**: `isSafeExternalUrl` 对内网/非法协议拦截率 100%。
2. **I/O 合并校验**: 高频并发调用 `saveJSON` 最终落盘数据需为队尾最新值。
3. **DOM 完整性校验**: `index.html` 必须精准包含精简后的 6 个核心 Tab 节点。

### 6.2 回归与性能测试门禁
- **语法门禁**: 全量 JS 模块运行 `node -c` 语法解析，报错数必须为 0。
- **流畅度测试**: AI 长文本流式回答打字过程中，视口帧率维持在 **55~60 FPS**，且手动上滚历史记录不被置底打断。
- **内存泄漏测试**: 连续播放/切换背景音乐 50 次，内存占用波动区间增幅 `< 5MB`。
